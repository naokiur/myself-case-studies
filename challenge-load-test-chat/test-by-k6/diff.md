# Locustとの比較

k6による負荷テストスクリプトの実装において、Locustと比較して以下の点が異なります。

## 1. Web UIの不在
Locustは実行中にWeb UI（デフォルトでlocalhost:8089）からUser数やHatch Rateを変更したり、特定のUserを選択してテストを開始したりできます。
k6には標準でこのような対話型のWeb UIはありません。そのため、実行時の引数や環境変数（`TEST_TYPE`）によって実行内容を制御する形式にしています。

## 2. 言語とビルドプロセス
LocustはPythonで記述し、そのまま実行可能です。
k6はJavaScript（またはTypeScript）で記述しますが、Node.js互換ではないため、TypeScriptを使用する場合はビルド（トランスパイル）が必要です。本プロジェクトでは `npm run build` を実行してから `k6 run` を行う手順となっています。

## 3. シナリオの定義
Locustでは `SequentialTaskSet` を使って一連の操作を定義しますが、k6ではデフォルトの関数内で順次関数を呼び出すことで同様の挙動を実現しています。
また、全APIのランダム実行（`user_all_apis.py`）については、Locustでは `tasks` 辞書に重みを設定するだけで済みますが、本スクリプトでは `Math.random()` を用いた条件分岐で重み付けを再現しています。

## 4. 目標スループット（RPS）の直接制御
LocustではUser数と `wait_time` を調整して間接的にRPSを制御しますが、k6の `constant-arrival-rate` エグゼキュータを使用すると、「秒間何リクエスト投げるか」という目標RPSを直接指定できます。
これにより、サーバーの負荷状況によらず一定の負荷を与え続けることが容易です。

## 5. 強力なメトリクスと閾値（Thresholds）
k6は標準で詳細なメトリクスを収集し、特定のAPIの成功率やレスポンスタイムが閾値を下回った場合にテストを失敗（終了コードを非0にする）させることができます。CI/CDへの組み込みがLocustよりも容易です。

## 6. リソース効率
k6はGoで書かれており、1つのOSスレッドで多数の仮想ユーザー（VU）を効率的に並行実行できます。PythonベースのLocustと比較して、同じハードウェアリソースでより高い負荷を生成することが可能です。
